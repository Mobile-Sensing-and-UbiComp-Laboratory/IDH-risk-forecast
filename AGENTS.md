# Stage 1: public-facing release

- This is `IDH-risk-forecast`, the public-facing stage-1 GitHub repository curated from `../IDH-task/`. It replaces the former local `IDH-task-release/` folder.
- Fetches and pulls need no conversational confirmation. Commit and push only when authorized by the user; if needed, ask once for both and choose a brief, descriptive commit message.
- Task authorization (including "go ahead") covers necessary Git operations and requested server synchronization, including follow-up fixes. Honor narrower instructions and do not ask for the same authorization again.
- Sandbox approval is separate from task authorization: Git network operations and SSH may still require tool approval prompts. Follow enforced permissions; these instructions cannot suppress those prompts.
- Read `../AGENTS.md` if present and start with `README.md` for the data contract and module usage. Inspect Git status and current files before editing; preserve user changes. Do not modify or synchronize changes back to the original stage-1 repository unless explicitly requested.
- Keep data, patient identifiers, private paths, credentials, model weights, generated results, and environments out of the release. Keep notebook outputs and execution counts cleared; do not add identifying metadata or attachments. Do not copy whole directories from the source repository.
- Retained scope: data preparation, non-VAE model files, `src/main_train_eval_multi.py`, `src/err_analysis.py`, `src/res_summary.py`, `src/inference_plot_new.py`, and the notebooks `calibration.ipynb`, `plots_results_for_1st_revision.ipynb`, and `SHAP_test.ipynb`. Deployment/database integration, intervention simulation, standalone VAE experiments, and ad-hoc exploration are excluded.
- The user explicitly approved retaining the active `VAE_Latent` helper. It affects training and checkpoint compatibility; do not remove it as unused code or as part of excluding standalone VAE experiments.
- Keep edits minimal and preserve the scientific pipeline. Remove obsolete/debug commented-out code, but preserve plausible experiment variations with a brief explanation. Historical alternatives may require interface adaptation; do not imply they were validated or silently enable them.
- Paths and sampling settings belong in `src/config.py`. Keep preparation, loaders, and model dimensions consistent: the core model consumes four physiological and four machine channels, 18 summary fields, and 192-dimensional EHR embeddings. Preparation also stores a fifth machine channel that core loaders omit. Preserve the original reference when assessing historical variants.
- Run scripts and launch notebooks from this folder. Verify dependencies, device, inputs, and output paths before execution; CUDA remains the default. Ask before long experiments, describing the command, compute needs, expected duration or uncertainty, and output location. Preserve existing data, splits, checkpoints, and results.
- Validation so far: syntax, local imports, path configuration, sensitive-literal scans, and structural comparisons of retained core computations. Comment cleanup was checked for identical ASTs and executable tokens across Python files and notebook code cells. End-to-end preparation, training, and notebook execution remain unverified; dependencies are unpinned and data/weights are not bundled.
- For comment-only changes, use syntax and AST/token comparisons to verify executable code is unchanged. Report checks and limitations concisely; do not launch training as a routine test.
